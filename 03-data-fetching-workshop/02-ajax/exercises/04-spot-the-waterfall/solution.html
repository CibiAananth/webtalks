Exercise 04: Spot the Waterfall — Solution

Optimized version with Promise.all for parallel requests

Key Optimization Insights

1. Independent requests run in parallel: /api/users, /api/users/1, and /api/users/2/posts don't depend on each other. Use Promise.all to fire them simultaneously.

2. Dependent requests still waterfall: /api/users/1/posts needs the user ID, and /api/posts/1/comments needs the post ID. These must wait.

3. Redundant requests eliminated: The original code fetched /api/users twice. We cache and reuse.
